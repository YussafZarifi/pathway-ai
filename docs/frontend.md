# Frontend

`frontend/` — React 19 + Vite 7 SPA, plain JavaScript, plain CSS.

## Entry & routing
- `src/main.jsx` renders `<App/>` in `StrictMode` and imports `index.css` (the only stylesheet).
- `src/App.jsx` — `BrowserRouter` → `ThemeGate` → `Routes`:

| Route | Page | Status |
|---|---|---|
| `/` | `Landing` | ✅ Hero + 3 feature cards (2 say "Coming soon"); header and hero CTAs → `/quiz` |
| `/home` | `Home` | 🟡 Hub: quiz CTA, the browser-saved roadmap with real progress and "Open your dashboard" (or an accurate "No roadmap yet" empty state, since 2026-09-29), planned-feature cards. Linked from the shared `AppHeader` on `/home` and `/dashboard`, not from Landing (ROADMAP P-9, was N-15). Becomes the signed-in dashboard after auth (ADR-010) |
| `/quiz` | `Quiz` | ✅ |
| `/results` | `Results` | ✅ Redirects to `/quiz` without `location.state.answers` |
| `/dashboard` | `Dashboard` | ✅ Redesigned 2026-09-26. Loads the stored roadmap (`lib/roadmapStore.js`), falls back to router state, shows an empty state (not a redirect) when there's none |
| `*` | `NotFound` | ✅ Branded 404 (since 2026-09-29, ADR-017): shared header, "404", "Return home" (`/home`), "Take the quiz"; tab title "Page not found · PathwayAI" |

## Pages
- **Landing.jsx** — framer-motion staggered hero. Hero elements start at `opacity: 0` (JS-dependent visibility). Header has Log in and Sign up buttons. With accounts on (Supabase configured, since 2026-09-30) they open `/login` (Sign up on the create-account tab) and a signed-in visitor sees "Your home" instead; with accounts off both open `AccountsSoonDialog` ("coming soon", "Take the quiz") as before. The hero "Get Started" CTA goes to `/quiz`.
- **Home.jsx** — "Welcome to PathwayAI" hero with quiz CTA; "Your roadmap": the roadmap saved in this browser (career, steps done from `getStepStatuses`/`summarizeProgress`, one roadmap per browser) with "Open your dashboard", or a "No roadmap yet" empty state (since 2026-09-29); "What you can do" with three real cards (quiz; Resume Analyzer → `/resume`; AI Coach → `/coach`; since 2026-10-07). Nav uses `NavLink`. No stats, activity or achievements are shown until real data exists. Visual polish pass 2026-09-26: own `.homePrimaryBtn` (gradient CTA), `.homeBadge` for "Planned" (the global `.comingSoonBadge` has conflicting definitions), no `resumeIcon`/`coachIcon` classes on cards (global rules with those names leak in); instead `homeFeatureIcon--roadmap/--resume/--coach` and `homeFeatureCard--resume/--coach` give the cards the Landing colours (pink, green, indigo) and tinted hover glows; every card floats on hover (6px lift, icon lift + 1.06 scale; disabled under reduced motion).
- **Quiz.jsx** (5-question assessment since 2026-09-28, ADR-016) — step state, `answers` object, progress bar, `AnimatePresence` transitions. Question types: `choice` (single, radio look), `multi` (grid, up to `max`, other options disabled at the limit, live "n of 3 selected"), `buttons` (four large buttons with values, used for weekly hours), plus an optional `followUp` text field with suggestion chips (the "career in mind" field under Q5, sent only when non-empty). Every option has `aria-pressed`; each group is labelled by its question. The slider type was removed. Tracks `quiz_started`, `quiz_question_answered` (outside the state updater; the free-text field isn't tracked per keystroke), `quiz_completed`, session start/end.
- **Results.jsx** (~700 lines) — fetches careers on mount through `requestCareers` (`lib/api.js`, AbortController), shows the letter loader, error state (Try again = full page reload, TD-40), empty state, career cards (icon via a keyword `if` chain, match %, salary, growth, skills, expand for reason plus `CAREER_DETAILS` overview), compare mode (a labelled checkbox in a `.careerRow` beside each card, never inside the card button, so comparing never changes the selection; up to 3; toggle "Compare Careers"/"Done comparing" with `aria-pressed`; since 2026-09-29), "None of these", regenerate suggestions, Generate roadmap → `repositoryFor(session).generate(...)` (guests: `requestRoadmap` + `saveCurrentRoadmap`) → `/dashboard`.
- **Dashboard.jsx** (redesigned 2026-09-26) — composes `components/dashboard/*` from `lib/dashboardData.js` derivations: `DashboardHero` (career, AI match %, progress ring, next milestone, time left, skills), `TodayFocus` (one task + first video, mark done / open step), four `StatTile`s (steps bar, learning materials, day streak, 14-day active days), `RoadmapStepper` (done/current/upcoming nodes, expandable details with tasks, videos, resources), and a rail with `AchievementGrid`, `InsightsPanel`, `QuickActions` (regenerate via `lib/api.js` with confirm dialog + skeleton, retake quiz, Resume Analyzer → `/resume`, AI Coach → `/coach`; since 2026-10-07). Data comes from `useCurrentRoadmap()` (loading and error states since 2026-10-03); marking a step done goes through `setStepDone` (guests: `trackProgress("roadmap_step_<roadmapId>_<i>")`) and emits `roadmap_step_completed`. A `#step-N` URL hash opens and scrolls to that step once the roadmap has loaded (since 2026-10-07). No tabs, no Employability/Momentum meters.
- **Resume.jsx** (`/resume`, since 2026-10-07, M3-5, ADR-020) — signed-in only. States: accounts off ("needs an account"), signed out (sign in, returns to `/resume`), then `GET /api/resume-analyses/availability` decides: feature off ("Resume Analyzer isn't available yet"), no active roadmap (link to the quiz), or the upload card (career shown, browser-side PDF/size checks via `lib/resume` `fileProblem`, analyzing state). Errors after load show the API's message; 401/409/503 re-check availability so the page follows a switched-off feature or a missing roadmap. A privacy card says what happens to the file. "Your reviews": history read from Supabase (newest 20), collapsible `AnalysisView` (summary with an "AI review" tag, skills shown / not shown, strengths, gaps with "Roadmap step N" — a link to `/dashboard#step-N` when the review was made against the current roadmap — suggested edits; no score), delete with a confirmation dialog. The file name is never displayed, stored, logged or sent; the request body is only the file's bytes.
- **Coach.jsx** (`/coach`, since 2026-10-07, M4-3, ADR-021) — signed-in only (accounts-off and signed-out states; sign-in returns here). `GET /api/coach/availability` decides between the chat and "isn't available yet". Left: conversations from Supabase (newest 30; open, delete with confirmation, "New"). Right: messages (user bubbles right, "AI Coach" replies left, text rendered as text), starter prompts, a typing indicator, a composer (Enter sends, Shift+Enter new line, 1,000-character counter, contact details refused before sending), a privacy note. Suggested actions are buttons (`CoachMessage.jsx`): open a dashboard step (`/dashboard#step-N`), mark a step done (only on click, through `useCurrentRoadmap().setStepDone`; disabled when already done), open `/resume`, take the quiz. Errors keep the draft; 409 offers a new conversation; 401/503 re-check availability. Message text is never stored in the browser or logged.
- **Step notes and reminders** (since 2026-10-07): every expanded step has "Your notes" (`components/dashboard/StepNotes.jsx`: a note ≤ 2,000 characters and a target date) saved through `useCurrentRoadmap().setStepNote` — the account through RLS (`step_notes`), guests in localStorage (`pathwayai_step_notes`). Step headers show "Due …" / "Overdue · …"; the dashboard shows a Reminders card (`getReminders`: unfinished steps overdue or due within 3 days, soonest first) with "Open step". In-app only (no emails).
- **Roadmaps.jsx** (`/roadmaps`, since 2026-10-07) — roadmap history for signed-in users: every saved roadmap (newest 20, from `accountRepository.history()`), current or archived badge, a progress bar, read-only steps on demand, "Make current" (`POST /api/roadmaps/{id}/activate`) and "Open dashboard" for the current one. Guests and accounts-off builds get an honest explanation. Reached from the Dashboard quick action "Past roadmaps" (signed-in) and Home's "All your roadmaps".
- **Settings.jsx** (`/settings`, since 2026-10-07, ADR-022) — signed-in only. Profile (email read-only, display name through RLS; the field stays disabled until the profile has loaded and a stale load never overwrites typing), password change (current password proven with a fresh sign-in, then `updateUser`), sign out of all devices (`signOut({ scope: "global" })`), download my data (`GET /api/me/export` + email and name → JSON file), delete account (dialog: password + typing DELETE; fresh sign-in, `DELETE /api/me`, local sign-out, then a "Your account was deleted" state). Reached from the header's email link.
- **ResetPassword.jsx** (`/reset-password`, since 2026-10-07, ADR-022) — where the reset email lands. Accepts a new password only for a recovery session (`AuthProvider.recovery`, from the `PASSWORD_RECOVERY` event or the link's `type=recovery`, read before Supabase consumes the URL); a normal session sees "This reset link isn't valid".
- **Login.jsx** (`/login`, since 2026-09-30, ADR-018) — email + password via `lib/supabase.js`: "Sign in" / "Create account" toggle (`aria-pressed`; `location.state.mode === "signup"` opens sign-up), optional name (sent as `display_name` sign-up metadata → `profiles`), password ≥ 8 characters, Supabase error codes mapped to fixed copy (raw errors never shown). Sign-up with email confirmation shows "Check your email" + resend (`emailRedirectTo` = `<origin>/home`); `email_not_confirmed` on sign-in offers a resend. Success → `location.state.from` or `/home`. "Forgot your password?" (since 2026-10-07) sends a reset link (`redirectTo` `/reset-password`) and always answers neutrally (no account enumeration). Error copy lives in `lib/authErrors.js`. Other states: already signed in, and "Accounts aren't available here" when auth is off. Guests get "Take the quiz as a guest".

## State management
- Local `useState` per page. No context or store.
- Quiz answers go to Results through `navigate(path, { state })`; Results also passes a fallback copy of the roadmap to the Dashboard.
- The current roadmap comes from `lib/roadmaps/useCurrentRoadmap()` (since 2026-10-03). For guests it is persisted by `lib/roadmapStore.js` (`pathwayai_roadmap`); events, metrics and step progress by `lib/trackingEngine.js` (`pathwayai_tracking`). See `docs/database.md`.

## lib/
- **api.js** — the only backend client (since 2026-09-27). `request()` adds the `VITE_API_URL` base (no fallback; `vite build` fails without it), a 90 s timeout (Gemini + YouTube + Render free-plan wake-up), caller `signal` support, and throws `ApiError(message, status)`. Optional `token` → `Authorization: Bearer` (since 2026-10-03). Exports `requestCareers`, `requestRoadmap` and `normalizeSteps` (step numbers + defaults), the saved-roadmap calls `createSavedRoadmap`, `regenerateSavedRoadmap`, `importLocalRoadmap` (ADR-019), and `errorMessage(error, fallback)`: 4xx/timeout/network errors show the specific message (e.g. rate limit), other failures the page's own copy.
- **roadmapStore.js** — `saveCurrentRoadmap`, `loadCurrentRoadmap`, `stepProgressKey(roadmapId, index)` (ADR-013).
- **roadmaps/** (since 2026-10-03, ADR-019, M2-8) — where the current roadmap lives. `index.js`: `repositoryFor(session)` picks the repository (signed in with accounts enabled → account, otherwise local) and documents the shared record shape `{ mode, id, career, careerData, answers, roadmap, generatedAt, statuses, canRegenerate, events, activityKind }`. `accountRepository.js` (M2-9): signed-in users — reads `roadmaps` + embedded `roadmap_steps` + `step_progress` through Supabase/RLS, marks/unmarks steps by inserting/deleting `step_progress`, generates and regenerates through `api.js` (FastAPI saves), derives activity events from saved rows (`activityKind: "progress"`). `localRepository.js`: the guest repository over `roadmapStore` + `trackingEngine` (same keys and formats as before; also the router-state "unsaved" fallback); `loadSync` lets guests render on the first frame. `useLocalImport({ enabled, onImported })` (M2-10): the guest-import offer — builds the payload from `pathwayai_roadmap` + its progress, `importLocalRoadmap`, then `clearProgress(roadmap_step_<id>_)` + `clearCurrentRoadmap()`; "Not now" stores the dismissed id in `sessionStorage` (`pathwayai_import_dismissed`). `useCurrentRoadmap({ fallbackState })`: `{ mode, status: loading|ready|error, record, error, reload, setStepDone (optimistic, reverts on failure), regenerate, setRecord }`. Pages use only these, never storage directly.
- **dashboardData.js** — pure derivations for the dashboard (progress, next milestone, time left from the AI's estimates, streak, achievements, insights).
- **supabase.js** — the single Supabase client (since 2026-09-30, ADR-018), built from `VITE_SUPABASE_URL` + `VITE_SUPABASE_PUBLISHABLE_KEY`. Either missing → `supabase = null`, `authEnabled = false`: no account UI, guest flow unchanged.
- **authContext.js** — `AuthContext` + `useAuth()` → `{ enabled, loading, session, user }`; filled by `components/AuthProvider.jsx` (wraps the router in `App.jsx`; `getSession()` + `onAuthStateChange`).
- **trackingEngine.js** — `trackEvent`, `trackMetric`, `trackProgress` (`started|completed|skipped|incomplete`), getters, sessions, export/import/clear. Validates against `data/trackingSchema.js`. ⚠ `getTrackingData()` writes back on every read; the event array is unbounded.
- ~~**scoringEngine.js**~~ — deleted 2026-10-07: imported nowhere since the Employability/Momentum meters left the dashboard (2026-09-26); measured engagement, not employability (TD-29, B-14).

## data/
- `questions.js` — the 5 quiz questions (`interests`, `problem_style`, `experience`, `weekly_hours`, `goal` + optional `career_in_mind`). **IDs are a contract** with `backend/schemas.py` (v2) and `backend/prompts.py`.
- `trackingSchema.js` — `EVENT_TYPES`, `METRIC_NAMES`, `EVENT_SCHEMA`, `validateEvent`.
- `careerDetails.js` — static details for 17 careers (includes non-tech roles left over from before the pivot). Looked up by exact AI title.

## Styling
- `src/index.css` (~4,400 lines): all pages. Design tokens on `:root` for the dashboard/home work (2026-09-26), but many raw hex and `rgba` literals remain elsewhere; duplicated selectors (e.g. `.comingSoonBadge`); a copied Uiverse loader; `"Inter"` referenced but not loaded. `:focus-visible` styles exist for the quiz options, Home, dialogs, video cards and the dashboard. `prefers-reduced-motion` rules cover only Home, video cards and the dashboard's CSS animations; framer-motion animations (Landing, Quiz, Results) ignore it because there is no `MotionConfig reducedMotion="user"` (TD-33, TD-34).
